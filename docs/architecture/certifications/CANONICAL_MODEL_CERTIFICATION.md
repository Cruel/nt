# Canonical Model End-to-End Certification

Certification date: 2026-08-28.

This record closes issue #135 by re-certifying the current #64 canonical model after the #116,
#129/#136-#141, and #130-#134 compliance work landed. It certifies the repository as it exists now;
it does not preserve the superseded #102-era Item Definition/Item Stack model and it does not create
or advance any compatibility version.

## Certified canonical model

The identity spine is now Interactable Definition plus exact Interactable Instance:

- Interactable Definitions provide reusable immutable configuration.
- Every live Interactable object has an exact `InteractableInstanceId`, one Definition reference,
  Location, enabled/visible state, and Instance-local Trait/Property deltas.
- Room occurrences point at exact declared Interactable Instances. Two Instances that share one
  Definition remain distinct runtime identities and save/restore independently.
- The former `ItemDefinition`/`ItemStack` authoring and Compiled Project collections are retired.
  Canonical positive fixtures do not use them. The strict decoder keeps negative coverage that proves
  retired Item Stack-shaped input is rejected rather than accepted as a compatibility alias.

Properties are owner-local state rather than globally keyed identity declarations. Traits are
self-contained Property contracts with ordered typed declarations and optional defaults; explicit
owner values resolve through the single runtime resolver ahead of Interactable Definition Defaults,
inherited Archetype Defaults, and Trait Defaults. Variables compile to Global Properties. Room,
Character, Interactable Instance, Feature, and Archetype authoring all use the same current Property
semantics, and schema-less dynamic runtime Properties survive checkpoint, save, decode, and restore
without inventing authored declarations.

No schema, protocol, Compiled Project, or save version was bumped for this convergence work. No dual
reader/writer, migration layer, compatibility alias, or positive retired Item/Stack path was added.
The repository schema-version policy remains the authority for those boundaries.

## Canonical executable projects

Six checked-in canonical fixtures are generated by the real TypeScript authoring compiler and then
consumed by the strict native Compiled Project decoder/runtime seam:

- `canonical-linear.json` is Room-free Scene -> Dialogue execution. It reaches a save-safe Dialogue
  checkpoint, restores through `RunningGame::prepare_load_candidate()` / `commit_candidate()`, resumes
  the exact Dialogue continuation, and completes the game.
- `canonical-exploration.json` starts in an ordinary Room and publishes Room, Map, Inventory,
  Feature, Interaction, and exact Interactable Instance state. Subject-first Interaction invokes a
  Scene that creates runtime world state, moves the exact `key` Instance into inventory, changes its
  visibility and owner-local `note` Property, mounts stateful Layout state, saves, restores, and then
  continues Room lifecycle/navigation behavior.
- `canonical-flow.json` drives one Dialogue through repeated Handoffs, including a staged-Room
  flashback and an ordinary parent-Scene interlude, and proves each return resumes the exact suspended
  Dialogue frame while staged presentation is unwound correctly.
- `canonical-fast-forward.json` starts at an authored input barrier, fast-forwards through awaited
  disposable presentation work and semantic Lua mutation, skips skippable duration work, and stops at
  the next real input barrier without executing work beyond it.
- `canonical-layout-signal.json` mounts a stateful authored Layout Slot, waits for a typed Layout
  Signal, saves/restores while waiting, reconnects the exact restored occurrence, validates signal
  payload fields, and resumes only after the accepted signal.
- `canonical-vocabulary.json` is an exhaustive current-wire fixture rather than a walkthrough. It
  covers the current closed Scene, Dialogue, Interaction, selector, runtime-world, gameplay mutation,
  presentation, Archetype, Trait, Property, Feature, and exact Interactable Instance vocabulary.

The golden generator is the only producer for these files. They are not hand-maintained native test
fixtures, so TypeScript compiler/native decoder disagreement fails the same generated boundary used
by publication and export.

## Runtime, checkpoint, and resolver certification

The focused native acceptance set exercises the current model through the final runtime seam rather
than through duplicate test-only implementations. It covers:

- strict canonical-vocabulary decoding and strict rejection behavior;
- owner-local Interactable Instance Value -> Definition Default -> inherited Archetype Default ->
  Trait Default -> missing resolution order;
- distinct declared Interactable Instances sharing one Definition across save/restore;
- effective Property validation for runtime-created Interactables;
- schema-less dynamic Property checkpoint/save/restore behavior;
- completed Room and nested Scene/Dialogue restore;
- exact/prefix/catchall Hook Registry resolution plus conflicting/invalid registry rejection;
- `On Game Ready`, Bootstrap, and Room lifecycle hook ordering/yield restrictions;
- subject-first Verb Offers and Guards, structural-tier/priority ordering, most-specific suppression,
  primary activation, equal-priority ambiguity diagnostics, and deterministic publication order;
- Feature subjects whose owner is a runtime-created Interactable Instance;
- staged flashback/repeated Dialogue Handoff continuation;
- Room-free, exploration, fast-forward, and Layout Signal `RunningGame` paths.

The canonical checkpoint tests preserve exact semantic identity. They do not substitute UI indexes,
screen coordinates, direction aliases, or arbitrary save payloads for runtime identity.

The complete native suite additionally retains the #64 failure-path coverage required by #135:
malformed/stale compiled shapes and semantic references are rejected; script capabilities and stale
runtime generations are enforced; runtime-world/configuration mutations remain atomic; incompatible
Layout State is rejected without consuming retained state; Save Contract mismatch invalidates the
candidate; invalid/restored Flow state is rejected without partially replacing the live session;
Dialogue/Gesture cues are emitted exactly once; retained/deferred checkpoint selection remains
revision-bound; suspended/waiting work reconstructs through restore; and failed reset/load candidates
preserve the current live session and Project VM.
