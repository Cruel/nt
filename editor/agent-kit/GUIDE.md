# NovelTea Agent Guide

This directory is generated by the installed NovelTea CLI. Run `noveltea agent sync` before relying
on it in a new agent session. The root `AGENTS.md` routes here; this file is the entrypoint for the
installed authoring contract.

Never edit `.noveltea/` as project source. It is disposable/tool-owned state and is replaced by sync.
Do not edit the NovelTea-managed block in the root `AGENTS.md`.

## Normal reasoning path

1. Read the relevant page under `.noveltea/agent/concepts/` to understand identity, ownership, and
   how the domain composes.
2. Read the matching generated page under `.noveltea/agent/reference/` for the exact current shape,
   defaults, variants, constraints, semantic notes, lifecycle notes, and checked examples.
3. Inspect nearby initialized project records. When a new top-level record is needed, prefer
   `noveltea entity create` to obtain a current canonical starting shape rather than inventing one.
4. Use `.noveltea/agent/schemas/` only when an exhaustive machine-oriented JSON Schema view is useful.
5. Make the complete coherent project edit, then run `noveltea validate` and relevant authored Tests.

Do not guess behavior from field names or JSON shape when the generated reference contains semantic
or lifecycle notes. Do not treat old examples from memory as more authoritative than the installed
reference.

## Source map

- Shared public model: `.noveltea/agent/concepts/overview.md`, then the focused concept page.
- Exact Project/record contract: `.noveltea/agent/reference/index.md`.
- File-first editing, workspace rules, CLI/transaction choices, localization, and validation:
  `.noveltea/agent/workflows/AUTHORING.md`.
- Layout/RmlUi/Lua/shader authoring surfaces that are not Project-schema concepts:
  `.noveltea/agent/technical/`.
- Exact built-in system Layout roles, baseline cascade, and source paths:
  `.noveltea/agent/system-layouts/manifest.json` and `.noveltea/agent/system-layouts/ui/`.
- Raw workspace-v1 JSON Schemas: `.noveltea/agent/schemas/`.

The shared concept pages and generated Project reference are the normal path. Technical documents
exist only for authoring languages/runtime surfaces that the Project schema cannot describe; they are
not a second Rooms/Characters/Interactions manual.

## Editing discipline

NovelTea projects are file-first. Edit tracked JSON, Lua, RML, and RCSS directly for ordinary field
changes. Use semantic CLI commands when an operation needs project-wide knowledge, canonical
initialization, transactional mutation, external tooling, or execution. `noveltea --help` is the
authoritative installed command list.

Finish all supporting records/references for one logical change before treating validation as final.
After direct edits to managed localizable Lua/RML, run `noveltea localization sync`; if identity is
ambiguous, use the reconcile workflow rather than guessing. Passive validation and preview never
materialize localization tracking.

Structural and behavioral validation is the agent's responsibility. Visual judgment such as whether
a sprite or hotspot is positioned attractively or precisely remains a user decision.

When the editor is open, continue editing tracked project source normally. If it reports a conflict,
resolve the tracked source or use the editor's conflict flow; never modify `.noveltea/` to bypass it.
