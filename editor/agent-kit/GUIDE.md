# NovelTea Agent Guide

This directory is generated by the installed NovelTea CLI. Run `noveltea agent sync` at the start of each agent session before relying on these files. The root `AGENTS.md` routes here; `.noveltea/agent/GUIDE.md` is the authoritative entrypoint for generated NovelTea authoring guidance.

NovelTea projects are file-first workspaces. Edit tracked JSON, Lua, RML, and RCSS directly for ordinary authoring changes. After direct edits to managed localizable Lua/RML, run `noveltea localization sync`; if sync reports ambiguous identity, use `noveltea localization reconcile` to obtain a revision/fingerprint-bound JSON plan and `localization reconcile --apply` with explicit resolutions, then run `noveltea validate`. Localization target work is normalized: use `noveltea localization view <locale>` (optionally status-filtered) for a joined source/target queue, `localization accept` for freshness acknowledgement, and `localization review` for human review of Current valid targets. Use the CLI for semantic operations that need whole-project knowledge or transactions: localization workflow operations, Asset import, create, rename, delete, usages, shader compilation, tests, and package export.

Never edit `.noveltea/` as project source. It contains disposable or tool-owned editor, transaction, cache, build, trash, and generated agent state. Follow the root `AGENTS.md` and do not edit its marked NovelTea-managed block.

## Normal authoring loop

1. Read the relevant shared concept page, then the matching generated reference for exact shape.
2. Inspect nearby existing project records for project-specific conventions.
3. Make the complete logical edit, including all supporting records and references.
4. If managed localizable Lua/RML changed, run `noveltea localization sync`; passive validation and preview never materialize that tracking. If ambiguity remains, inspect `noveltea localization reconcile --json` output and apply an explicit resolution plan rather than guessing identity.
5. Run `noveltea validate` after the coherent edit rather than validating every temporarily incomplete intermediate state.
6. Run relevant authored tests when they exist and the requested behavior is testable through the CLI.

Structural and behavioral validation is the agent's responsibility. Visual judgment such as whether a sprite or hotspot is positioned attractively or precisely is left to the user.

When the editor is open, continue editing tracked project source normally. If the editor reports a conflict, resolve it through the editor or the tracked source involved; never modify `.noveltea/` to bypass it.
