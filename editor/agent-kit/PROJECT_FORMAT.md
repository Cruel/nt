# NovelTea Workspace v1

The project root is the directory containing `project.json`. Follow the generated workspace-v1 schemas and current file layout; do not create retired monolithic project files or legacy alternate shapes.

Editable project source lives in `project.json`, `traits.json`, `editor.json`, `i18n/`, `records/`, `scripts/`, `shaders/`, and `assets/`. Game localization is chunked under `i18n/`: `project.json` owns Source/Default locale policy and the persisted Source-locale lock; `messages.json` owns explicit Messages and structured Message identities; `usage-notes.json`, `tracking.json`, and `orphans.json` own translator occurrence notes and managed localization bookkeeping; sparse target work lives in `locales/<locale>.json` and localized Asset targets in `assets/<locale>.json`. Do not recreate the retired top-level `localization.json`. Once substantive target translation or localized-Asset work exists, the Source locale is locked for v1; do not edit `sourceLocale` or its managed lock to migrate languages. There is no top-level identity `properties.json`: identity Property schemas and Values/Defaults belong to their exact owner, reusable Trait, Archetype, or Interactable definition. `project.json` also owns the exact `interactableInstances` registry. Root `AGENTS.md` contains project instructions; follow it and do not edit its marked NovelTea-managed block. Never edit or track `.noveltea/` as project source.

Record filesystem identity is derived from the stable record ID, not the label. IDs match `^[a-z][a-z0-9]*(?:-[a-z0-9]+)*$`. Non-Layout records live at `records/<collection>/<id>.json`; Layouts live at `records/layouts/<id>/layout.json`. A record ID must match its canonical path.

Current record collections include Assets, Variables, Materials, Layouts, Archetypes, Characters, Rooms, Interactables, Verbs, Interactions, Dialogues, Scenes, Maps, Script Modules, and Tests. Shader source is ordinary project source under `shaders/`, not a record collection. The generated `schemas/records/` directory contains one schema for each tracked record collection; use the focused docs first to understand semantics, then consult the schema for exact fields and variants.

Layout RML and RCSS use `{"sourceMode":"file"}` or `{"sourceMode":"asset","sourceAsset":...}` in `layout.json`; dedicated Lua uses `{"sourceMode":"file"}` or `{"sourceMode":"none"}`. Lua Asset mode is obsolete. File-mode companions are `layout.rml`, `layout.rcss`, and `layout.lua` beside `layout.json`.

Script Modules persist as `{"kind":"project-file","path":"scripts/...lua"}`. Script file paths use forward slashes, remain under `scripts/`, cannot contain empty/`.`/`..` segments, and after symlink resolution must remain inside the project root. Two Script Modules cannot own the same normalized or real source file. Those containment and unique-ownership constraints are executable workspace rules beyond what JSON Schema alone can prove.

Tracked JSON is UTF-8, LF, two-space indented, and ends with one newline. Do not add timestamps, absolute machine paths, cache values, or local session state. Do not rewrite unrelated files as formatting fallout.
